# Structure — Goi

## Repository layout
```
goi/
├── SPEC.md                  # Product spec (source of truth for scope)
├── CLAUDE.md                # Agent guidance (created at Phase 5)
├── .claude/
│   ├── steering/            # product.md, structure.md, tech.md
│   └── designs/<feature>/   # requirements.md, design.md, tasks.md, retro.md
├── main.go                  # Wails entrypoint: wires app + bindings
├── app.go                   # Wails App lifecycle (startup/shutdown/dom-ready)
├── wails.json               # Wails project config
├── go.mod
├── internal/                # goi-core: all backend logic, UI-agnostic
│   ├── workspace/           # open folder, roots, excludes, project detection
│   ├── vfs/                 # file read/write, tree listing, fs watcher
│   ├── gosdk/               # GOROOT discovery, `go env`, `go list`, versions
│   ├── settings/            # layered TOML settings: defaults → user → project
│   ├── format/              # gofmt / goimports on save
│   ├── recent/              # recent projects store
│   └── rpc/                 # Wails-bound service facades (thin; no logic)
├── frontend/                # Wails frontend (TypeScript + Vite)
│   ├── src/
│   │   ├── app/             # shell layout, tool-window docking, panels
│   │   ├── editor/          # CodeMirror 6 setup, languages, gutters
│   │   ├── palette/         # command palette / search everywhere
│   │   ├── keymap/          # keymaps (default, VS Code-style)
│   │   ├── theme/           # themes + editor color schemes (tokens)
│   │   ├── views/           # project tree, welcome screen, settings UI
│   │   └── lib/             # generated Wails bindings wrappers, utils
│   └── wailsjs/             # GENERATED by Wails — never hand-edit
└── build/                   # Wails platform assets (icons, plist, manifests)
```

## Architectural boundaries
1. **`internal/` must not import Wails.** It stays UI-agnostic so it can later run as a headless/remote `goi-core` daemon (SPEC §2.3).
2. **`internal/rpc/` is the only bridge.** It holds thin facades bound to Wails that translate calls and events to and from `internal/*` packages. No business logic.
3. **Backend → UI events** go through one event emitter interface (`rpc.Events`) so the transport can later move from Wails events to JSON-RPC over WebSocket.
4. **Frontend never touches the filesystem or spawns processes.** Everything goes through bindings.
5. **`frontend/wailsjs/` is generated.** Wrap it in `frontend/src/lib/` and import the wrappers, not the generated files.
6. Packages depend downward only: `rpc → workspace/vfs/gosdk/settings/format/recent`. Domain packages don't depend on each other unless the design says so.

## Project-local state
- `.goi/settings.toml`: project settings (shareable).
- `.goi/runConfigurations/*.toml`: arrives in M3.
- User state: `os.UserConfigDir()/Goi/<major.minor>/` (settings, recent projects, window layouts keyed by workspace hash).
- Caches: `os.UserCacheDir()/Goi/<major.minor>/`.
